Integrasi SDK

Dua alur terpisah: definisi flag (sync/cache) dan evaluate (per request per user). Dokumentasi repo: docs/guide/sdk/sdk-flagclient_id.md · contoh: examples/golang-service

Dua alur integrasi

  • Definisi flag — enabled, value, rules, version. WebSocket flags.snapshot + delta, atau GET .../flags. Satu set definisi per project/environment, tidak per user.
  • Evaluate — POST .../flags/evaluate dengan userId + attributes → value, reason, source. Wajib untuk rules dan rollout; Variation() dari cache lokal tidak menjalankan targeting penuh.

Konsep Flag Gen → menjelaskan arsitektur; halaman ini fokus ke kode dan endpoint.

Project key vs Project ID

  • Project key — label manusia di dashboard (mis. development).
  • Project ID — UUID di baris Projects; dipakai di path API dan query WebSocket projectId=.
  • Environment key — mis. production; ada di path .../environments/:environmentKey/....

Environment variables (local / contoh Go)

  • FLAG_GEN_BASE_URL — base API, mis. http://localhost:6123/v1
  • FLAG_GEN_PROJECT_ID — UUID dari halaman Projects
  • FLAG_GEN_ENVIRONMENT_KEY — mis. development
  • FLAG_GEN_API_KEY — API key server untuk evaluate
  • BROADCAST_DEV_TOKEN — harus sama dengan server .env agar WebSocket tidak 401
  • FLAG_GEN_POLL_FALLBACK=true — opsional; polling HTTP hanya fallback

Server: OUTBOX_WORKER_ENABLED=true, BROADCAST_CONSUMER_ENABLED=true, RabbitMQ aktif.

Referensi endpoint

Browser — list GET /v1/client/projects/:projectId/environments/:environmentKey/flags
Browser — evaluate satu flag GET /v1/client/.../flags/:flagKey/evaluate?userId=...
Server — evaluate POST /v1/projects/:projectId/environments/:environmentKey/flags/evaluate
Backend — broadcast GET /v1/broadcast/flags?projectId=...&environmentKey=...&token=...

Checklist live update tidak jalan

  • Log service: websocket connected — jika 401, set BROADCAST_DEV_TOKEN.
  • Dashboard ubah flag → dalam beberapa detik service harus log flag updated tanpa redeploy.
  • RabbitMQ dan worker broadcast aktif di server flag-gen.
  • Jangan mengandalkan polling sebagai jalur utama — WebSocket adalah desain utama.
